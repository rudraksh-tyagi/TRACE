# TRACE — Marine Oil Spill Intelligence System

## Frontend Documentation

TRACE is a college-level SIH prototype for marine oil-spill investigation.

The frontend provides a professional investigation dashboard that visualizes the complete workflow:

Satellite Detection → Spill → Source → Drift → Vessels → Evidence → Ranked Candidates


## 👨‍💻 Frontend Role

Member 6 — Frontend, Visualization & Integration Engineer

Main Responsibility:

Build the actual frontend interface and connect the outputs of the other project modules into one complete working demonstration.

Frontend Handles:

- Main dashboard
- Interactive maritime map
- Oil-spill visualization
- Spill intelligence
- Drift visualization
- Probable source region
- Vessel trajectories
- Candidate vessel ranking
- Source compatibility visualization
- Evidence/explanation display
- Backend API integration
- Light/Dark mode
- Loading and error states
- Final SIH demonstration interface

Frontend Does NOT Handle:

- AI/ML model development
- AI/ML training or inference
- SAR image processing
- GIS calculations
- Ocean drift calculations
- AIS data processing
- Vessel attribution algorithm
- Backend development

These modules are handled by other team members.


## 🎯 Project Purpose

TRACE behaves as a Marine Oil-Spill Investigation Console, not a generic AI dashboard.

The frontend is designed to help an investigator answer five core questions:

1. Where is the spill?
2. How large is it?
3. Where could it have come from?
4. Which vessels were there?
5. Why is a vessel ranked highly?

The frontend can display:

- Probable source region
- Source time window
- Uncertainty radius
- Backward drift
- Forward forecast

Backward drift helps estimate where the oil may have originated.

Current Spill
      ↓
Backward Drift
      ↓
Probable Source Region

Forward movement can be displayed as:

Current Spill
      ↓
Forward Forecast

The frontend only visualizes the drift results provided by the backend.

It does not perform the ocean-drift calculations itself.

## ⚠️ Attribution Terminology

TRACE is an intelligence and investigation prototype.

The frontend must not claim that a vessel definitely caused the oil spill.

Do NOT use:

- Guilty Vessel
- Confirmed Responsible Vessel
- Vessel That Caused The Spill

Use:

- Potential Source Vessel
- Candidate Vessel
- Top Candidate
- Highest Source Compatibility
- Source Compatibility Score
- Probable Source Region
- Detection Confidence

Recommended wording:

"This vessel is ranked highly based on available spatial, temporal and trajectory evidence."

This keeps the interpretation evidence-based and avoids presenting a probabilistic ranking as a confirmed conclusion.

## 🔌 Backend API Integration

The frontend communicates with the backend through REST APIs.

Primary Endpoint:

GET /api/incident/complete

The unified incident response can contain:

- incident_id
- spill
- drift
- ranked_candidates
- metadata

Available API Endpoints:

GET /health
GET /api/spill
GET /api/drift
GET /api/vessels
GET /api/attribution
GET /api/incident
GET /api/incident/complete

The frontend consumes these APIs and visualizes their outputs.


## 🩺 Backend Health Status

The frontend uses:

GET /health

to determine whether the backend is available.

Possible states:

● SYSTEM ONLINE

or

● BACKEND OFFLINE

The frontend should also provide:

- Refresh
- Retry
- Loading state
- Error state

The application should not crash if the backend is temporarily unavailable.


## 🟠 Demo Mode

During development and college demonstration, the backend can use:

USE_MOCK_DATA=true

This allows the backend to return mock/demo data through the same API endpoints.

The frontend does not create a separate mock API.

The frontend continues to call the normal backend endpoints.

When the real AI/ML, GIS, Drift and AIS modules are connected, mock mode can be disabled and the same frontend can consume real outputs.
